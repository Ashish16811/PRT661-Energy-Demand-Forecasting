# WP4 Integration Contract

**Source of truth:** `Energy_Demand_Forecasting_Pipeline.py` v4.0.0 — the version recorded in `environment/run_environment.json` of the final run (2026-09-29, 426.7 minutes, status COMPLETE).
**Scope:** the four role-aligned WP4 modules and the shared contract module in `Individual_Code/`.

These WP4 modules are current role-aligned collaboration artefacts prepared from the team's integrated implementation for genuine branch-based review and merging. They do not replace or re-date any earlier work. Results are generated by the integrated pipeline; no module hard-codes a model-performance outcome.

## 4. How the GRU halves connect

```
Suraj: known_future_matrices(panel, rd, maps) -> D, E
Suraj: training_starts(y, origin_pos, spec)   -> starts
Sudip: split_train_validation(starts, origin_pos) -> tr, va
Sudip: fit_gru_scalers(y, D, limit, index, DECODER_FEATURES) -> bundle
Suraj: build_sequence_batch(bundle.target.transform(y), E, bundle.feature.transform(D), tr/va, spec, origin_pos)
Sudip: train_gru(...) -> net, history, best, lr_path ; refit_gru(...) on all starts
Suraj: recursive_forecast(lambda e, d: net.predict_on_batch([e, d]), RecursiveSequenceState(...), grid_pos, E, D_s, bundle.target)
```

## 6. Equivalence rule

`python run_wp4_equivalence_tests.py --results <run folder>` must pass after every merge. It checks configuration equality, feature names and order, scaler behaviour, validation boundaries, sequence windows, parameter counts, identical-seed predictions/weights, and re-derives published MLP metrics from the interval detail (maximum difference 5e-5 on the final run).

If any check fails, or a change alters model behaviour (features, parameters, seeds, recursion, weather policy, selection rule), the PR is labelled `rerun-required`: **FULL ACADEMIC RERUN REQUIRED** before the WP4 results can describe that code.
